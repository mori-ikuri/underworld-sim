# underworld-sim

感情エンジンと記憶（鞄）を積んだ小さな個体たちを、箱庭の中でひたすらシミュレートし、感情の動きを観測・記録する実験プロジェクト。

## 狙い

最終的な目標は、**感情の判定（出来事から、相棒の感情がどう動くかを読む）に特化した小型LLM** を作り、重みと評価つきで公開すること。
このリポジトリはそのための土台で、役割は2つ：

1. **観測**：感情の連鎖（接近・回避・喧嘩・謝罪・仲直り）がどのような条件で生まれるかを、再現可能な形で記録する
2. **データ生成**：判定モデルの学習・検証に使うサンプルを、記号ログから一貫した形式で生み出す

進め方は「評価を先に作る」「ラベルの出どころを1件ごとに記録する」「状態はAIの外に置く」を原則とする。
（2026-11-12 開始）

## これは何か

- 12×12マスの小さな世界「Underworld」に、個体Aと個体Bがいる
- 各個体は **感情エンジン**（8次元の感情状態＋ベースラインへの減衰）と **鞄**（記憶）を持つ
- 内側のシミュレーションは記号ログだけで回り（LLMなし）、1ステップ＝1時間
- LLMが登場するのは、個体が1日の終わりに鞄を振り返って日誌を書くときだけ
- 出来事はまず「相手から」生まれる（相手と接触しなければ感情は動かない）。記憶の想起による感情の再燃など、要素は実測しながら段階的に足していく

## 観測したいもの

- 怒りの増幅（接近→回避される→さらに怒る）
- 不安の解消（接近→会話→翌日の相互接近で不安が下がる）
- 蓄積されたログは、将来「感情の判定に特化した小型モデル」の学習データになる想定

## 状態

v1.0：シミュレーション本体（Python・標準ライブラリのみ・依存ゼロ）が動作する。
設計メモは [docs/design-2026-11-12.md](docs/design-2026-11-12.md)、記号ログの仕様は [docs/log-schema.md](docs/log-schema.md)。

## 動かし方

```bash
# 100日分を seed 固定で実行（出力先フォルダに結果一式が保存される）
python -m underworld run --days 100 --seed 42 --out runs/run1

# 同じ出力先にもう一度実行すると、保存された状態から「続き」を回す
python -m underworld run --days 30 --out runs/run1

# 最初からやり直す
python -m underworld run --days 100 --seed 42 --out runs/run1 --fresh

# 既存ログの集計だけを見る
python -m underworld analyze --log runs/run1/log.jsonl

# テスト
python -m unittest discover -s tests -v
```

出力ファイル：

| ファイル | 内容 |
|---|---|
| `log.jsonl` | 記号ログ（1行1イベント）。仕様は [docs/log-schema.md](docs/log-schema.md) |
| `state.json` | 実行状態そのもの（乱数の内部状態を含む）。プロセスの外に置かれ、実行をまたいで継続できる |
| `summary.json` / `summary.md` | イベント種別ごとの件数、日次集計、検出されたエピソード、最終状態 |
| `diaries.md` | 各個体の日誌（全日分） |

パラメータ（閾値・確率・半減期・ベースライン・各種増減表）はすべて `config/default.json` に外出ししてある。
`--config` で別JSONを指定すると、既定値に深くマージして上書きできる。

## 感情判定サンプルの生成

ログ v2（`appraisal` キーつき）から、感情判定モデルの学習・検証用サンプルを作る。
形式・正解の作り方・分割ルールは凍結済みの仕様
[docs/appraisal-sample-spec-v0.6.md](docs/appraisal-sample-spec-v0.6.md)（v0.6、2026-11-21 凍結）が正で、
サンプルの JSON Schema は [docs/sample-schema.json](docs/sample-schema.json) に置く。

```bash
# run ディレクトリ（log.jsonl と run.json を含む）を渡す。run 単位で
# 学習／検証／テストに割り当ててから、train.jsonl / val.jsonl / test.jsonl を出す
python -m underworld samples --runs runs/run1 runs/run2 --out samples

# 試しデータ一式（気質ランダム10本＋係数1.0の seed42、すべて摩擦は strength 方式）と集計
python tools/trial_runs.py
```

- `run.json` には `run_id`・`seed`・個体ごとの `coefficients`（気質）と `thresholds`・`config_hash`・`generator_commit` を書く。
- 分割は run（＝気質の組み合わせ）単位で先に決める。テスト側の気質の組み合わせは学習・検証に出ない。
- Schema 検査を含むテストには開発用依存（jsonschema）が要る：`pip install -r requirements-dev.txt`。シミュレーション本体とサンプル生成は標準ライブラリのみ。
- なお `examples/` のログは v1 のままで、`appraisal` キーは付いていない（回帰テストの正本として固定してある）。サンプル生成にはログ v2 の run が要る。

## 観測できるもの

サマリには、ログから自動で切り出した「エピソード（出来事の連鎖）」が載る。

- **パターンA**：接近 → 回避される → 怒りが増幅する
- **パターンB**：接近 → 会話 → 翌日の相互接近で不安が解ける
- **喧嘩 → 回避 → 謝罪 → 仲直り** の修復連鎖

サンプル実行（100日・seed 42）は `examples/run-seed42-100d/` に同梱してある。
2400ステップが1秒未満で回り、FRICTION 26回・FIGHT 87回・APOLOGY 9回・SURVIVAL 28回、
エピソードはパターンA 1件・パターンB 4件・仲直り 4件が検出された。
（怒り側のチューニングにより、我慢強い個体Aが閾値を超えて怒りで接近し、
回避されるパターンAが自然発生するようになった。）

## 日誌とLLMについて

日誌は「diary provider」という差し替え可能な部品が生成する。既定はテンプレート方式で、
**LLMは一切使わない（トークン消費ゼロ）**。LLM方式は差込口だけが用意され、既定で無効。
使う場合も「1日2回・要約済みログのみ・安価なモデル・上限を先に見積もる」が設計方針。

## 注意

- 状態はプロセス外のファイル（`state.json`）に置く。「状態はAIの外に置く」という開発者の一貫した設計思想どおり。
- 分割して実行した場合、その日の日誌は「その実行で得たログ」から組み立てられる。
- これは感情のシミュレーションであり、実在の誰かの感情ではない。

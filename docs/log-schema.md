# 記号ログ スキーマ仕様（log.jsonl）

シミュレーションのすべての出来事は、1行1JSONオブジェクトの記号ログ（JSONL）として記録される。
内側のループにLLMは入らず、解読（文章化）はこのログを読む側の仕事である。
コストは「回した量」ではなく「読んだ量」に比例する、という設計の要。

**v2（2026-11-22）**：感情判定サンプル仕様 v0.6（`docs/appraisal-sample-spec-v0.6.md`）の §9.1〜§9.3 に対応し、一部のイベントに `appraisal` キー（後述）を追加した。`appraisal` キーを外せば v1 と同じ1行に戻る。あわせて、個体ごとの感情係数（§9.2）と、摩擦の強さ方式（§9.3-1）を設定で選べるようにした。

## 共通フィールド

| フィールド | 型 | 意味 |
|---|---|---|
| `step` | int | シミュレーション開始からの通算ステップ（0始まり）。1ステップ＝1時間 |
| `day` | int | 日番号（1始まり）。`step // 24 + 1` |
| `clock` | int | そのステップの時刻（0–23）。1日は 7:00 始まり |
| `type` | string | イベント種別（下表） |
| `kind` | string? | 種別内の小分類（任意） |
| `actor` | string | 主体の個体ID（`"A"` / `"B"`）。日誌など個体に属さない場合は省略されうる |
| `target` | string \| null | **対象**の個体ID。相手がいるイベントでは必ず入る。個体が増えたときの移行コストを消すため、1:1の現状でも冗長に持たせる（設計メモ決定事項）。単独イベントでは `null` |
| `effects` | object? | 感情の変化。`{個体ID: {次元: 変化量}}` の形で、変化量は状態値（0..1）の実増減。0の次元は省略される |
| `detail` | object? | 種別ごとの補足（閾値・距離・結果など） |
| `appraisal` | object? | v2で追加（下記）。サンプルにする種別（NOTICE・LOST_SIGHT・REACT・CONTACT・FRICTION・FIGHT・APOLOGY）にだけ付く |

## appraisal（v2）

感情判定のサンプル作りの正本データ。出来事ごと・関わった個体ごとに、その出来事で「切られる前の点数」と「直前の状態」を記録する。`effects`（0..1に切ったあとの実増減）からは正解を作らない、という仕様 §9.1 の決定を受けたもの。

```
"appraisal": {
  "A": {
    "state_before": {"joy": 0.29, "sadness": 0.05, ...},   // その出来事の直前の8次元
    "points_pre":  {"anger": 8.0, "trust": -2.0},          // 慣れの割引のあと・係数の前の点数
    "points_post": {"anger": 8.0, "trust": -2.0},          // 係数を掛けたあとの点数（状態に足されるのはこちら）
    "grudge": false,                                       // 恨みで点数が変わったか
    "tables": ["greet_warm"]                               // その個体に当てた deltas の表の名前（下記）
  },
  "B": { ... }
}
```

- **関わった個体**：片方だけが感じる出来事（NOTICE・LOST_SIGHT・REACT）は感じた側だけ。CONTACT・FRICTION・FIGHT・APOLOGY は二人とも。点数が全部0でも記録する（`no_change` と「関わっていない」を分けるため）。記録のない次元は点数0として扱う。
- **points_pre / points_post**：点数は「表の点数 → 慣れの割引 → 恨みの割引（×0.4）→ 係数」の順で加工され、`points_pre` は係数の直前、`points_post` は係数の直後の値。状態への反映は `points_post × point_scale` を 0..1 に切って行われる。
- **tables**：その出来事でその個体に当てた `config.deltas` の表の名前のリスト。当てた順に並び、重複はない。点数を直接足すだけの出来事（NOTICE の支配感情の増幅など、表を使わないもの）では空リストになる。文章化（デコード）の側は、挨拶の相手の様子（相手の `tables` に `greet_warm` があれば「にこやか」）と、距離を取ったのが誰か（`keep_distance_self` を当てた側）を、この名前から決める。点数の形からは決めない――恨みの割引で点数が変わると形が崩れ、文と正解が食い違うため。
- **grudge**：恨みの割引（好意・喜びのプラスの ×0.4）が効いたときと、気づいたときの再燃（NOTICE の `detail.grudge_reignite`）の両方で `true` になる。仕様 §9.3-2 により、この印のある件はサンプルから外す。
- **係数（§9.2）**：`config` の `individuals.<ID>.coefficients` に次元ごとの係数を持てる（既定はすべて 1.0）。掛けるのは点数だけで、半減期・閾値・ERODE には掛けない。
- **摩擦の強さ方式（§9.3-1・§11.1・§11.2）**：`contact.friction_mode` が `"strength"` のとき、摩擦ごとに強さを3段階（重み `contact.friction_strength_weights`、既定は均等）から一度だけ選び、あわせて、どちらがぶつけたかを半々のくじで一度だけ選ぶ（直し方B）。ぶつけられた側には怒りの点数（`contact.friction_strength_anger_points`、既定は 2・5・8）と信頼 −2（`deltas.friction`）が当たり、ぶつけた側は怒りなし・信頼は動かず、悲しみ（`contact.friction_strength_sadness_points`、既定は段階そのまま 1・2・3）だけが当たる。選んだ段階は `detail.strength_stage`（1・2・3）と `detail.strength_anger_points`・`detail.strength_sadness_points` に、ぶつけた側は `detail.bumper`（`"A"` / `"B"`）に残る。`appraisal` の `tables` では、ぶつけられた側に `friction`、ぶつけた側に `friction_bumper` と記録される。文章化の側はぶつけた側を `detail.bumper` から決め、点数の形からは決めない。ログの版は v2 のままで、強さ方式の FRICTION の detail に `bumper` が1つ増えただけである。既定の `"per_person"` は従来どおり個体ごとに jitter でばらつき、くじも引かない（乱数の並びは変わらない）。

感情次元は8つ：`joy`（喜び）`sadness`（悲しみ）`anger`（怒り）`fear`（不安）`surprise`（驚き）`affection`（好意）`trust`（信頼）`fatigue`（疲労）。
いずれも 0..1 で、ベースラインと半減期は `config/default.json` の `emotions.dimensions` に従う。

## イベント種別

| type | kind | actor / target | 意味 |
|---|---|---|---|
| `NOTICE` | `spot` / `eye_contact` | 気づいた側 / 相手 | 相手が視界（半径3）に入った。気づくは「発生器ではなく増幅器」：その相手への支配的感情を少し増幅する。`eye_contact`（距離2以内）では驚きも上がる。根に持っている間は怒りが微再燃する（`detail.grudge_reignite`） |
| `LOST_SIGHT` | — | 見失った側 / 相手 | 相手が視界から出た。好意・不安が支配的なときだけ不安・悲しみが少し上がる |
| `INTERRUPT` | `approach` / `flee` | 割り込んだ側 / 相手 | 相手への感情（好意・怒り・不安の最大値）が個体の閾値（A=0.55、B=0.35）に達し、目的地が相手に割り込まれた。`detail` に `emotion`・`value`・`threshold`・`dest` |
| `SURVIVAL` | `food` / `rest` | 本人 / 相手 | 空腹・体力が限界域（空腹 ≥ 0.9 / 体力 ≤ 0.1）に入り、生存系が感情の割り込みを上書きした。発動した瞬間に1回だけ記録 |
| `REACT` | `avoided` / `mutual_approach` | 反応した側 / 相手 | 相手の反応を見たことによる感情変化。`avoided`：接近したのに相手が離れた（接近感情が怒りなら怒り増幅、好意なら不安・悲しみ）。`mutual_approach`：互いに接近し合い、不安が下がる |
| `CONTACT` | `greet` / `together` / `keep_distance` | A / B（ペア） | 隣接時の接触の解決結果。`greet`：挨拶・会話（片方が温かい、または両者平常）。`together`：両者の好意が支配的で一緒に過ごす（連続接触で増分が割り引かれる＝慣れ。`detail.habituation_factor`）。`keep_distance`：不安が強い側が距離を取る |
| `FRICTION` | — | A / B（ペア） | 事故（摩擦イベント）。接触ごとに約8%で発生する「怒りの種」。既定では怒りの量は個体ごとに僅かにばらつく（受け取り方の差）。`friction_mode: "strength"` のときは強さ3段階とぶつけた側（くじ）を一度だけ選び、ぶつけられた側に怒り+・信頼−、ぶつけた側に悲しみだけが当たる（上記 appraisal の節を参照） |
| `APOLOGY` | — | 謝る側 / 謝られる側 | 片方だけが怒り、もう片方が温かい（好意・信頼が高い）ときに起きる謝罪の試行。`detail.result` が `accepted`（怒り−中・信頼+）/ `rejected`（相手の怒りが深すぎて届かず、謝った側の好意が少し下がる） |
| `FIGHT` | — | A / B（ペア） | 両者が怒り支配的で接触し、喧嘩になった。両者 怒り+・好意−。直後に各自 `AVOID start` が続く |
| `AVOID` | `start` / `end` | 回避する側 / 相手 | 回避モードの開始・終了。回避中は感情の割り込みが抑えられ、相手から離れることが目的地になる。ただし怒りが本人の割り込み閾値以上に達した場合は例外で、回避を破って相手へ向かう（`INTERRUPT` が優先）。怒りが下限以下に下がると終了 |
| `GRUDGE` | `start` / `end` | 本人 / 相手 | 「根に持つ」状態の開始・終了。怒りが一定以上になると一定期間、怒りの減衰が緩み（半減期×3）、相手を見かけるたび微再燃し、本人の好意・喜びのプラス増分が割り引かれる（減圧1） |
| `ERODE` | — | 回避中の側 / 相手 | 回避が丸1日以上続いたことによる信頼・好意の目減り（減圧3）。ベースライン未満には絶対に下がらない（不在ペナルティなし原則）。累積が一定量に達するたびに記録 |
| `EAT` | — | 本人 / null | 食材スポットで食事。空腹がリセットされ、喜び+・疲労− |
| `REST` | — | 本人 / null | 休憩場所で休息。体力が回復し、疲労− |
| `SLEEP` | — | 本人 / null | 就寝（日誌の直後）。睡眠中は接触イベントが発生しない |
| `WAKE` | — | 本人 / null | 起床。眠気リセット、疲労− |
| `DIARY` | — | 本人 / null | 就寝直前の日誌。`detail.text` に文章が入る。生成は diary provider（既定はテンプレート方式、LLM不使用）に委ねられ、将来差し替え可能 |

## 再現性と継続性

- `--seed` で乱数を固定する。同じ seed・同じ設定・同じ日数なら、ログはバイト単位で一致する。
- 実行状態は出力先の `state.json`（乱数の内部状態を含む）に保存され、同じ出力先へ再実行すると続きから再開する。
- エピソード（連鎖）の検出は `underworld/episodes.py` が担い、ログだけから再計算できる。検出型は3つ：
  パターンA（接近→回避される→怒り増幅）、パターンB（接近→会話→相互接近で不安解消）、喧嘩→回避→謝罪→仲直り。
